# Короткий опис моделі та відповідальності основних класів. 

- Client — відповідає за зберігання даних про клієнта автосервісу (ім'я, контактний телефон).
- Car — описує автомобіль (марка, модель, рік випуску, VIN-код та посилання на власника-клієнта), містить логіку валідації VIN.
- Mechanic — зберігає інформацію про робітника автосервісу (ім'я, спеціалізація, статус зайнятості).
- Job — описує конкретну роботу, що виконується в межах замовлення, включно з назвою та вартістю (з використанням типу BigDecimal).
- Order — ключовий бізнес-клас, який об'єднує автомобіль, призначеного механіктора, список робіт та керує життєвим циклом замовлення за допомогою OrderStatus (enum).
- CarService — центральний клас системи, який зберігає списки клієнтів, автомобілів, механіків і замовлень та надає методи для керування ними.

CarService 
- Містить загальні списки: Client, Car, Mechanic, Order
 
Order
- Car -> Client 
- Mechanic 
- List<Job>

# Коротка рефлексія щодо використання ШІ, якщо він використовувався.
Під час виконання роботи штучний інтелект використовувався як інженерний помічник. 
З його допомогою було згенеровано демонстраційний клас CarServiceDemo та тестові сценарії для перевірки позитивних і негативних кейсів роботи програми. 
При цьому було прийнято самостійне рішення використовувати строгу типізацію статусів через enum OrderStatus замість звичайних рядків, як пропонував ШІ, 
щоб гарантувати правильний життєвий цикл замовлення та унеможливити помилки в коді.


# Висновок
У ході виконання даної лабораторної роботи я розробив консольний застосунок на Java для управління автосервісом та закріпив основні принципи об'єктно-орієнтованого програмування.
Я навчився застосовувати інкапсуляцію для захисту даних класів, використовувати BigDecimal для точних фінансових розрахунків, реалізовувати валідацію та обробку винятків,
а також протестував роботу програми на різних сценаріях і успішно завантажив готовий проєкт на GitHub.
